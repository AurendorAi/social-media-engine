# Produce, inspect, repair

This is the producer's working loop, not an independent review or a new runtime state
machine. Keep notes in the selected workspace and reference the exact exported revision.
Use existing item/review commands and contracts; do not submit these working labels as
runtime enum values. Self-inspection cannot satisfy independent review roles.

1. **Plan against evidence.** Use the [composition contract](design-patterns.md). Check
   the proposed headline against sources and the planned image against available assets.
   Catch a false premise before rendering. Preserve the approved brand constraints.
2. **Make the actual output.** Discover available tools, compose with real copy and
   approved materials within the [no-new-vector production boundary](../SKILL.md#production-boundary-no-newly-created-vector-graphics), export the requested format and preserve editable source. A prompt,
   storyboard or source file alone is not a finished rendered deliverable.
3. **Inspect the current artifact.** View native resolution and a phone-sized presentation;
   inspect every carousel frame in order and full video playback with sound. Record the
   artifact path/hash and concrete observation: “the comparison labels disappear at phone
   size,” not “typography 8/10.” Check claims, payoff, brand recognition, hierarchy, crop,
   script coverage, sequence and the chosen pattern's visible acceptance check.
   When the renderer exposes text bounding boxes, require a measured check after fonts
   load: compare every line with BOTH the canvas safe area and its intended container's
   padded content area in the same coordinate system. Record the tool result and exact
   revision; if measurement is unavailable, state that limitation instead of inferring
   a pass from coordinates, font sizes or planned placement.
   Record overflow and repair it before review; follow the [text rendering
   guidance](creative-production.md#text-rendering-and-script-checks)
   where applicable. Bounds are a diagnostic, not a substitute for inspecting actual
   exports at native and phone sizes; they cannot certify shaping or visible clipping.
4. **Repair the cause.** Pair each observation with an edit and expected visible effect.
   If the subject is too small, enlarge/re-crop it and remove competing text. If the point
   has no evidence, change the claim or obtain evidence; a color change cannot fix it.
   If a sequence repeats itself, remove the redundant frame or give it a different job.
   Render a new revision and compare the affected view with the prior export. Recheck
   the entire item for regressions, especially text changes and shifted safe zones.
   A repeated layout failure requires rebuilding the affected region, not another
   cosmetic nudge. Repeated bidi failure requires a simplified text render and observed
   proof before reintegration; follow the concrete fallback in creative production.
5. **Stop on an evidenced condition.** Use the labels below to communicate progress.
   Never keep polishing merely to raise a score or invent feedback to finish the loop.

| Working label | Evidence and next action |
|---|---|
| Ready for independent review | Actual current exports inspected; concrete observed defects resolved; required deliverables and sources present. Submit exact hashes for existing review roles. This is not approval. |
| Needs substantive revision | A visible, repairable mismatch remains. Record observation → edit → expected effect, then produce a new revision. |
| Blocked by missing evidence or rights | A required claim, asset or permission cannot be verified. Identify the exact missing input; produce only a clearly scoped truthful alternative if authorized. |
| Blocked by capability | The host cannot render, view, play, shape required text, or export the required format. Save source/draft, name the missing capability and offer a supported alternative. Do not claim pixels were inspected. |
| Awaiting independent review or owner decision | Producer inspection is complete but independence, brand clarification, review or explicit approval is outstanding. Present actual files and the precise decision needed. |

Default to at most two focused repair passes after the first export per sample. This is
a budget for autonomous iteration, not a quality waiver: if the same material defect
remains, save the best draft and report the unresolved cause and next step. Continue when
the user has authorized further iteration or new evidence/tools make progress possible.
Do not turn an unfinished batch into “complete” because the pass budget was exhausted.

The independent reviewer may request another revision. After any edit, run the existing
hash-bound reviews again; past reviews and approval do not transfer. Show before/after
observations to the owner, not invented audience reactions or unsupported performance
improvements. Save reusable preferences only through the existing owner approval flow.

Use evidence verbs literally in source notes, alt text and handoff: “planned to check”
is not “tested” or “validated.” Claim inspection only when a tool or person actually
viewed the current export; record what was inspected and its result. Alt text describes
the visible content, not a quality certification. A generated assertion that text is
clear, correct or within bounds is not a measurement or independent review.
