# Choose and prove the production workflow

The plugin bundles brand memory, workflows and the review studio. It does not bundle
paid services, fonts, external skills or a renderer. Discover the host's actual tools
before promising a medium. Read the relevant installed tool/skill instructions.

All methods follow the [no-new-vector production boundary](../SKILL.md#production-boundary-no-newly-created-vector-graphics).
Layout and compositing tools remain available for text and existing assets; none is an
exception permitting model-authored vector art, code-drawn objects or rasterized vectors.

## Capability check

Before the first production batch, save a short capability note in the brand workspace:
capability; available tool/version; required access or cost; intended use; limitation.
Update when the host or production needs change. If current capabilities cannot meet
the brief, search available plugin catalogs or official tool sources for a suitable
option, explain the benefit, and follow the host's installation/authorization rules.
Don't install a broad stack merely to fill a checklist. Don't keep producing weak media
when a specific missing capability is the cause. Propose a feasible alternative.

| Job | Appropriate methods | Evidence required |
| --- | --- | --- |
| Research and copy | Host model, source browsing, supplied research, language editing | Claim/source notes and edited argument |
| Brand typography and layouts | Text layout and raster compositing with a renderer, Canva, Figma or a local design tool | Final pixels, editable source, real font identity |
| Original imagery | Available raster image generation/editing, licensed photography, owner assets | Output file, rights, reference usage, generation provenance |
| Product demonstration | Capture an authorized actual interface with a suitable screen recorder | Capture source, date, environment, demo-data disclosure |
| Motion explanation | Available motion compositor such as Remotion, HyperFrames or an editor | Storyboard, editable project, timing, native renders |
| Narration/music | Available voice tool or real recording; licensed music/sound | Consent where needed, audio files, rights, timing |
| Captions and delivery | Transcription/caption tools, media probing/encoding | Proofread captions, actual decode and playback |

These are examples, not mandatory providers. Text/media composition in code must respect the production boundary; generation alone
does not establish quality. Encoding a
slideshow does not automatically create a well-directed film.

## Prove one piece before scaling

Choose a representative complex composition and render it at the real target size.
For motion, render an actual excerpt with the key demonstration, type, captions and
sound. Inspect the artifact, repair it, then expand to the batch. Do not present a
contact sheet as full playback or a storyboard as a finished video.

For each shot, state: what the viewer learns; what changes visibly; source asset;
composition; on-screen text; voice/sound; duration; transition; production method.
Give every layer a role. Make the decisive number, field, action or expression prominent.
Avoid adding paper props, stock people, textures, diagrams or photography just to fill
space. Show a mechanism changing when the subject is a mechanism.

When multiple ratios are requested, compose each for its viewing conditions. Don't
stretch, pad or crop away the essential argument. Preserve complete shaped words when
animating connected scripts. Use the brand's actual approved fonts; verify font loading
and glyph coverage in the render, not just in source declarations. If absent, resolve
an approved fallback before finishing.

## Compact provenance in the content record

The item's `creative` object can contain:
- `idea`, `visual_mechanism`, `direction`, `editable_source`, `storyboard`;
- `production`: actual tool names/versions and the job each performed;
- `sources`: capture/generated/stock/owner provenance and rights notes;
- `exports`: ratio, dimensions, duration where relevant, local file or asset ID;
- `qa`: actual inspected exports, reviewer, observations, unresolved limits;
- `learning_applied`: relevant approved rule IDs and the visible effect.

Planned tools are not tools used. Use actual files and evidence. HTML source is not
final media; a passed schema is not an aesthetic review. Don't insert unverified model
output, simulated account data or placeholder artwork into production-ready records.

Before rendering, follow [resource sourcing](resource-sourcing.md) to find, inspect and
compose suitable real materials. Keep the brief, actual sourced ingredients, editable
composition and final rendered files distinct. Use AI where it helps the concept.
