# Get meaningful imagery with the capabilities actually available

Use for every image-bearing post and the first-content style comparison. Determine
capabilities from discovered tools and successful outputs, never from a host/model name.
One host may have image generation in one session and lack it in another. A missing
native generator is a routing condition, not a reason to abandon visual content or fill
it with generic geometric substitutes.

## Discover once, refresh on change

Keep a short capability note in the private workspace: native raster generation/editing;
web/image search and browsing; built-in public-library adapters; owner asset library;
connected Canva or another design/media service; available external generation API;
local raster/3D renderer; composition/export tools. For each record available, unavailable,
or authorization needed, actual tool/access, cost and constraints. No imaginary calls,
account access, hidden installs or secret-bearing notes. Bundled commands work without a
native image model; no third-party renderer or paid API is bundled.

## Select a route for the exact visual idea

Write the image's job first: what subject/action/evidence must the viewer see, what crop
and resolution the final post needs, and what cannot be substituted. Choose from the
routes below based on fit and quality, using zero-acquisition-cost materials first when
suitable. They are alternatives, not a requirement to exhaust every provider.

| Capability and material fit | Action | Proof before composition |
| --- | --- | --- |
| Relevant owner assets already exist | Inspect and reuse the selected brand's permitted photography or real product/interface capture | Actual file, permitted use and exact subject accuracy |
| Native image generation unavailable, or a real photo is preferable | Search available public web/image tools and libraries; the bundled `resource-search` supports `openverse`, `commons`, `met` and `iconify` (existing icons only) | Original asset page, applicable rights, actual downloaded pixels and adequate crop resolution |
| Canva or another asset/design service is connected | Discover its actual search, asset, editing and export capabilities; use suitable licensed imagery in an editable composition | Verified access, relevant asset and permitted use/export; a connection alone does not imply a stock search or download API |
| Native raster image generation is available and suits the concept | Generate the needed scene/element, then place exact brand text separately | Successful output, generation provenance, inspected pixels; do not present invented products/results as real |
| No native generator, but a suitable external image model/API is available | Use that actual tool/API under its access, cost and transmission rules; a small code client may call an authorized image model | Returned image bytes, actual provider/model and applicable rights; code is the client, not evidence of a generated image |
| A local renderer can produce the idea convincingly | Use a capable raster/3D render or raster compositing workflow when the subject warrants it; code is allowed for this purpose | Actual high-quality render at output size, editable scene/source and provenance for all ingredients |
| None can supply the needed imagery | Try a materially different source/query or recompose around a truthful, relevant available image; use typography only when it communicates the same idea well | Honest explanation of any material change; if no suitable output is possible, keep the gap explicit and request the specific missing asset/access |

Code may orchestrate image APIs, render a legitimate raster/3D scene, crop/composite
existing media, and lay out type. Do not use it to bypass the existing prohibition on
new vector illustrations, icon/shape drawings or rasterized vector artwork. A procedural
raster or 3D route is acceptable only when its actual output is strong enough for this
idea; default shapes, a graph of boxes or a rough diagram are not a substitute for a
meaningful photographic hero. Quality is judged from the result, not the tool category.

## Source and verify, then use the image

Follow [resource sourcing](resource-sourcing.md) for candidate records, licence evidence,
reviewed acquisition, credits and material use. Public search thumbnails are leads, not
production assets. A Canva design/template can be licensed for use without permission
to extract and redistribute its raw stock photos. Use permitted service exports or a
separate licensable source. Never strip watermarks, infer rights from availability, or
send private references to external services without the user's authorization.

For API errors, quota/cost/access blocks, unavailable browsing or poor generated output,
record the actual failure and switch to an available route. Do not keep retrying the
same failure or quietly describe generated media as sourced photography. Respect the
existing budget and authorization; no paid purchase or new credential request by default.
Search only the non-confidential visual idea, not the full private brief.

Inspect candidates at the final crop: subject/action fit, authenticity, anatomy or
physical coherence, focal point, negative space, distractions, embedded text, rights,
brand exclusions and pixel quality. Reject irrelevant but attractive stock. Do not make
claims from a conceptual scene. Compose the selected image into the actual post, add
editable typography, and inspect the final original/mobile export. Acquiring an image,
returning a URL, or writing a prompt is not completing the post.

Record the actual route, source/generation details, edits, rights, material IDs where
applicable, and any unresolved limitation in existing `creative.production`,
`creative.sources`, `creative.sourcing` and `creative.material_uses`. Do not invent new
runtime fields or claim a fallback was executed when it was merely available.
